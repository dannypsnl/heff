# Changelog

## Unreleased

### Standard library

- std.http.server's handler answers with a `Reply` (`serve`, `serveUntil`, `serveConnection`), no longer an `HTTP.Response`: a handler as it was is wrapped, `pure (Whole res)`, and `serveConnection` now asks for `exception Net.NetError` too. A `Reply` is a response whole (`Whole`); a `Head` -- a record of a status and headers, `{ status = 200, headers = hs }` -- and a body that yields its pieces, stream's `yield` of `Bytes` (`Streamed head body`), each written as it is yielded -- a chunk of `Transfer-Encoding: chunked` to HTTP/1.1, the connection closed after it to HTTP/1.0, the head alone to a `HEAD`; or a `Head`, after which the connection is the handler's function's (`TakenOver head f`), given the request, the connection and what was read after the request -- for an upgrade, a WebSocket's. A piece not written, the client gone, is the write's `NetError` thrown in the body at its `yield`, so its `with`s let go as a throw leaves them; the server hears it and closes the connection. What a head read comes to, the `Head` that was, is `HeadRead`. std.http.sse: server-sent events, each event its fields (`Event`, `Data`, `EventId`, `Retry`, `Comment`), sent by a streamed body (`send`), in a reply that says `text/event-stream` (`reply`).
- std.http.websocket: WebSocket (RFC 6455), its pure part, no socket read or written. `handshake` checks a std.http.server `Request` -- a `GET` of HTTP/1.1, `Upgrade: websocket`, `Connection: upgrade`, `Sec-WebSocket-Version: 13`, a key -- and comes to its accept key (`acceptKey`, for `upgradeHeaders`, the `101`'s), or the response refusing it, `400`, or `426` with `Sec-WebSocket-Version: 13`. `decodeFrame` reads a frame from the bytes read so far, or says how many more it wants, or refuses it with its close code (a client's frame not masked, an RSV bit set, an opcode not known, a control frame in pieces or over 125 bytes: 1002; over `most` bytes, 16 MiB by default: 1009); `encodeFrame` writes a server's, `encodeMasked` a client's. `feed` is a reader's state machine: bytes in, the messages they finish out -- pieces put together, a control frame between them a message of its own, text and a close's reason checked as UTF-8 (1007) -- and the reader to read on by.
- std.http.websocket over std.http.server, which serves one connection at a time: `accept`, a handler's `Reply` to a request asking for WebSocket -- its handshake refused, a response whole; else `101`, and the connection taken over given to a function as a `Connection`. `receive` pulls the next message of text or of bytes, with the connection to receive the one after by (`Arrived`), or the end (`Ended`, the close's code and why): a ping on the way answered by a pong, a close by a close, a breach of the protocol by a close of its code; what was read with the request is read first. `send` writes a message, not masked; `close` sends a close and waits for the client's. A read or a write failing, or waiting longer than `idle` (30 s by default, by name), throws its `NetError`, as a streamed body's `yield` does, and `accept` hears it and the connection is closed.
- std.crypto: public-key signatures as JWS has them, RS256, PS256, ES256 (its `r` and `s`, 64 bytes) and EdDSA (Ed25519), signed and verified by OpenSSL's libcrypto in a C program (linked by pkg-config's `libcrypto`; no page's): private and public keys read from PEM (PKCS#8, SubjectPublicKeyInfo, RSA's and EC's own), public ones made of a JWK's fields; a private key's public one (`publicOf`), a public key written as PEM (`publicKeyToPem`). Only a key some algorithm signs with is read or made: an RSA key of fewer than 2048 bits (`minRsaBits`, NIST SP 800-131A's least) is refused as it is read, by PEM or JWK, and so is a key of another curve or kind (P-384, DSA, X25519) or a JWK's RSA exponent even or under 3. A key or signature not made is `Left` of an `Error`: `Unreadable` (with OpenSSL's reason), `Encrypted`, `Unsupported`, `InvalidKey` (a JWK's fields that are no key, or a private key whose numbers are none: a P-256 scalar out of the curve's range, as it is read, an RSA key's that sign nothing, as it signs), `TooShort bits`, `WrongKey` (the algorithm's, signing with a key of another kind) or `Failed` (OpenSSL out of room); a signature that is not the key's is `False`.
- std.http.bocserver answers streams and WebSocket, pushed: a handler's responder takes an `Answer`, `respond (Whole res)` for a response as before, and `Responder` names the server's world and what the handler throws, `BocServer.Responder e err`. `Streamed head { opened, gone }`, `head` std.http.server's `Head`, writes it (chunked to HTTP/1.1; to HTTP/1.0 no length, closed after; to a `HEAD` the head alone), then gives `opened` a `Sender Bytes`: a value with no region in its type, kept in any cown and sent by from any behaviour (`send`, each piece queued on the connection's cown in order, never waited for; `finish`, the last chunk, the connection read on for the next request). `Upgraded { opened, received, gone }` checks std.http.websocket's `handshake`, writes its refusal or `101`, and reads frames an act at a time: each message of text or bytes a behaviour given to `received`, pings answered, a close answered and the connection closed, a broken frame closed with `feed`'s code; its `Sender WebSocket.Message` writes frames. `gone` is called once when the connection goes before the stream is finished (client gone, read at once while the stream goes on; server stopped), and at a socket's end. `serve` takes `pending` (1 MiB; more unwritten bytes than that closes the connection, the sender never waits), `heartbeat` (15 s; a `text/event-stream` stream is sent a `:` comment after that much silence) and `ping` (30 s; a silent socket is pinged, and closed when silent as long again), by name; a socket is not held to `idle`. Stopping the server ends streams and closes sockets (`1001`). std.http.sse has `headers`, a stream of events'.
- std.http.broadcast: one thing sent to many of std.http.bocserver's senders. A `Group` (`newGroup`) splits its senders into shards, each a cown, as many as boc's pool has threads (`BOC.workers`; no `process` needed) unless `shards` is given by name; `join` and `leave` put a sender in and take it out (by its `senderNumber`, so `{ opened = Broadcast.join g, gone = Broadcast.leave g }`), `finish` takes it out and finishes it after what was broadcast before, and `broadcast g x` is one behaviour on each shard, sending `x` to its senders, the shards in parallel. Broadcasts one after another come to each sender in that order. `size g k` counts the senders, a shard after another.
- boc's `workers`: how many threads the program's pool runs behaviours on (as many as the machine has cores; 1 in JavaScript), asked of `boc` alone, and without opening the pool.
- boc: the same cown twice in one `with` (or `when`) is a failure said as it is spawned, `` heff: boc: the same cown twice in one `with`, its 1st and 2nd cowns: the behaviour not spawned ``; the behaviour is never queued and the one spawning it goes on. It abandoned the spawner before, saying only `heff:abandon`.
- std.http.server and std.http.bocserver read a request's body sent in chunks (`Transfer-Encoding: chunked`), until then answered `501`: the handler's `Request.body` is the chunks' data, whole, each chunk's extensions and the trailer let go of; `100 Continue` is written as for a `Content-Length`. Chunks beside a `Content-Length`, or in HTTP/1.0, are `400`, as either may be what a proxy before the server went by; another coding (`gzip`) is still `501`; a chunk not as RFC 9112 says it, `400`; data past 64 MiB, `413`. `feedChunks` reads such a body a piece at a time, pure (`chunks`, nothing read yet; `Dechunked`, what a piece comes to), and `requestIn` comes, a request not all read, to what it still wants (`Wanted`: `MoreHead`, `MoreBody`, `MoreChunks`), no longer a pair.

## 0.6.1

Released 2026-10-31.

### Language

- A `with`'s condition is `once p`, not `where p`: after the last binding, on its line (`with s := stock once s >= n do`), or on a line of its own under more bindings, `do` at its end. `once` is a keyword. `where` is an equation's local definitions alone again.
- A binding of a `with` may be a pattern, `with (bytes, count) := total do`: what it is bound to taken apart, its names the body's variables; where the body sets one of them, the value is built back from them and written, else given back as it was.
- An act a `with` awaits, `with r := BOC.await act do`, needs no annotation of its world: the `with`'s `Holder` decides it, in a concrete `main` as in a polymorphic function, and in a world a handler adds to (`attempt`'s, `recover`'s). Generally, where the end of a definition would refuse evidence whose world is not known (E0357), each instance argument still waiting that is not evidence is taken first by its one candidate, though that decides its goal's metavariables, and settling goes on; only where that does not settle the definition is E0357 said, as before.

### Standard library

- heff's concurrency is boc's: std.domain, cml, std.thread and std.http.cmlserver are removed. boc is the runtime's own effect, no longer a library on std.domain (lib/boc.provider.c, and lib/boc.provider.js in a page): a program names `BOC.boc` in its world, `main : Co (BOC.boc <+> stdio) Unit`, and `Cown a` has no world parameter. A body, and an act awaited, is a computation of the world the `when` (the `with`) is in, mapped by the handlers between there and the program's world. The program is the scope: its behaviours run on one pool of as many threads as the machine has cores, opened by its first operation of boc's, and the program ends once `main` has and no behaviour runs and no act is pending; `scheduled` is gone, and so is `scheduledWithReactor`. `with r := BOC.await act do` runs `act` in the reactor of the worker that takes it, and `BOC.awaitFirst a b` races two, the other given up. An act awaited in a custodian's custody is given up as it is shut down. What took a domain or a thread is a behaviour; what waited, an act awaited; a cell or a channel, a cown, read out by a behaviour spawned after the one that wrote it, or one that waits until it holds what is wanted (`with x := c where p do`). Nothing waits for behaviours to come back with a value: what they come to is given on (`parMap`'s `k`). `Domain.tried` has no successor: exception's `attempt` and `recover` catch what is thrown; `Domain.fail why` is prelude's `panic why`. A behaviour or an act that fails -- abandons, panics, or fails in the runtime -- is said on stderr, the others go on, and the program ends by 1. A server is stopped by closing its listener, or by shutting down the custodian its acts were awaited in. std.thread's `cores` is std.process's `processors`. std.http.bocserver serves many connections at once.
- `panic why`, prelude's: a failure, `why` its words, of any type -- as `abandon`, which says nothing. At the top level it is said on stderr (`heff: why`), exit 1; in a behaviour of boc's, that behaviour fails, its cowns as they were, `why` said the same way, and the others go on.
- boc's `parMap f xs k`: `f` of each of `xs`, each by a behaviour on a cown of its own, at once; `k` given the results in order by a behaviour once all are done.
- std.net's `acceptedOwned`: `accepted`, the connection put in the custody of the custodian current too, so that shutting that custodian down closes it.
- boc no longer asks for the custodian's effect: a behaviour, and an act, takes the custodian current where its world has it, and none where it has not. A world without it no longer reaches the runtime's custodians: std.domain's `rooted` is gone, and with it the custodian's provider bundled with a program that did not ask for it.

## 0.6.0

Released 2026-10-29.

### Language

- `Show` is now `Debug` (`debug x`: the value as the source writes it, a string quoted, as Rust's `Debug`), and `ToString` is now `Show` (`show x`: text for a reader, as Rust's `Display`). Instances are named so: `instanceDebugInt`, `instanceShowString`.
- Instance search: a goal with unsolved metavariables is taken at once by its one candidate where that candidate fits it without deciding any of them (`Binder (Co ?e a)` by an instance for `Co e a`), instead of waiting; so `with f := File.open path do` needs no annotation.
- Evidence search: `h <: e` whose world is known but whose effect has an unsolved parameter, `boc ?w <: boc e <+> e`, is found by the one leaf of the world it fits, which solves the parameter; so a body given to `scheduled`, to a `spawn` or to a `with _ := CML.threads do` needs no `(w := e)`. Only a world not known where the call is stays E0357; an effect that fits more than one leaf waits for its parameter, and is E0356 at the end.
- Lazy values: `~A` is the type `Lazy A`, `~e` delays `e` until it is forced (#107).
- A theory's fields are fixed by named application, `Th (t := Bool)`, replacing `Th ~ { t = Bool }`. `~` is now an ordinary operator symbol.
- `T @ { x = v, y = w }` specialises a theory again, decided at parse time. Named arguments name arguments only.
- Instance search: a specialised goal is searched by its theory and parameters, then the found instance's fields are unified with the goal's (E0354). A field given by an instance argument not found yet waits for the search instead of failing with E0311.
- Tuples: `()` is the unit and `(a, b)` a pair, `(a, b, c)` is `((a, b), c)`; each says its type (`Unit`, `Pair`), so `pure ()` needs no annotation. Where a type is expected, `()` is `Unit` and `(A, B)` is `Pair A B`, and types print so. The same forms are patterns, and patterns now bind in `p <- e`, `with e as p` and `\p -> e` as well as `let p = e`; a pattern there that can fail is non-exhaustive (E0317).
- E0317 says `non-exhaustive pattern: no case provided for ...`.
- `let p = e else s` in a `do` block: `p` may fail to match, and `s` runs where it does; `s` must leave the block, by `return`, `break`, `continue` or `abandon` (E0203 otherwise).
- `if let` is removed: write a `case`, or `let p = e else s`.
- In a `do` block, `then` and `else` may start a line under their `if`, as outside a block; an `else` under an `if` is that `if`'s, and in an `else if` chain, the first `if`'s. `heff fmt` lays them out so.
- `if <- c then ...` and `case <- c of`: what an `if` tests or a `case` matches may be the value of an action, as `(<- c)`.
- `(x := _)` finds evidence `h <: e`: where `e` is a sum by `<+>` known at the call, the one place of `h` in it (through the evidence in scope where a part of it is a world of its own). None is E0355, more than one E0356, no `h <: e` or no world known E0357.
- Evidence `h <: e` asked for by an instance argument and not given, where no evidence in scope is it, is found as `(x := _)` finds it, so nothing need be written: `main = program`, `attempt FileError (load path)`, `print "x"` in `main`. Evidence in scope that fits is still taken first, once the world is known; until it is, the evidence in scope of the effect says the effect's parameters (`n <- get` under `{{st : state Int <: e}}`), but not which evidence it is, so that `attempt FileError c`'s `c` finds `stdio` through the `io` in scope. None is E0355, more than one E0356, no world known by the end E0357.
- An application of a function with implicit arguments, checked at a function type (a computation's, `Co e a`), is unified with it before its arguments are elaborated, where the function's type says what the application's is whatever the arguments are: a `do` block's `bind` knows its world before its statements, so each statement's evidence is found where it is wanted (a 120-statement `do` 0.27 s to 0.08 s). A `with`'s resource that would leave its body is said so where it is used.
- exception's `attempt err c`: the rest of the world, `e`, is implicit, found from where the result is used, as `main`'s type.
- `plus` is gone: effects are summed by `<+>` alone. `<:` binds looser than `<+>`, so `h <: h <+> k` is `h <: (h <+> k)`.
- `xs <- for x in c do body` gathers each turn's value, what its last statement comes to, into a list, in order; a turn left by `continue` gives none, and `break` ends the gathering. A `for` alone runs for its effects, as before.
- A signature may name more than one definition, `x, y, z : T`, at the top level, in `where` and `mutual`, and for a theory's or a record type's fields (`{ x, y : Int }`).
- `with x := M do`, a `with` of bindings (#129): any number of `x := M`, each on a line of its own under the first, handed to the handler as one group, by co's theories `Binder` and `Holder`; the names are variables of the body, which is a block of its own, and the handler is told which of them it sets. boc's cowns (`with a := c0` and `b := c1` under it: one behaviour on both, a cown only read not written back) and std.file's `open path` have instances. `x <- with ... do` binds what it comes to.
- A `with` of bindings may run its body in a world of its own, made from the block's: co's `Binder` has a field `World : HFunctor -> HFunctor`, `\w -> w` unless given, and `Holder` a parameter `world` after `contents`, its `held` given the body as a computation of `world e` to handle into `e`. `\w -> state Int <+> w` gives a body a count of its own; `\w -> stdio <+> w`, an output its holder writes to a file or a buffer. The body's evidence is found in that world, an effect it adds before the same effect in `e`, the others through the evidence in scope. Binders need not change; a `Holder` instance writes `(\x -> x)` for the world of the block around.
- Evidence wanted before its world is known no longer takes its effect's parameters from the evidence in scope where the world has a part that is that effect: `runState 3`'s computation's `get` under `{{st : state String <: e}}` reads its own `Int`. To know it, an application checked at a computation type whose answer is not known yet, `Co e ?a`, is given its world first where that is the head's own metavariable and an argument is of that world (`bind`'s, `runState`'s), and evidence asked for by a head waits until the head's world is unified with what it is checked at. A 120-statement polymorphic `do` 778 M to 759 M instructions; one of 40 `get`/`put`/`print` rounds 1055 M to 1004 M.
- `with x := M where p do`, a `with` of bindings with a condition (#135): `where p` on a line of its own under the bindings, `do` under `with`. What the names are bound to is taken and `p` checked of them; where it does not hold, all is let go of, untouched, and taken again later, until it holds. `p` is an expression of the names, with no action in it. The holder needs co's `Waiter` beside `Holder`, its `heldWhere` given which names the body sets, which `p` reads and `p`; a holder without one (a file, a scope of domains) is a type error. boc's cowns have one: a behaviour whose condition does not hold lets go of its cowns and waits until a behaviour writes one its condition reads, then is queued again behind that one (the paper's `whenever`); one still waiting once every other behaviour is done is dropped.
- Octal integer literals, `0o644`, beside hexadecimal `0x1a4` and binary `0b110100100`; `_` separates digits, `0o7_55`.
- `^` groups to the left: `s ^ a ^ b` is `(s ^ a) ^ b`, so a string grown a piece at a time is grown in place, each piece appended to it, not joined to the next first. A function ending in `x ^ "," ^ f xs` still appends a piece at a time. str_concat 19.5 G to 16.9 G instructions, base64_sha256 41.2 G to 37.0 G, graphemes 27.8 G to 26.0 G.

### Standard library

- Time zones (#126), as NodaTime has them: std.datetimezone's `DateTimeZone` (`offsetAt` an instant; `mapLocal`, a date-time's offsets there, `Unique`, `Skipped` or `Ambiguous`), read in heff from a TZif file's bytes (`fromTZif`, RFC 8536, its footer's POSIX rule after its last change) or from a POSIX `TZ` rule (`fromPosix`); std.zoneddatetime's `ZonedDateTime`, made by `at` an instant or by `resolve`, the program saying what a date-time skipped or gone back over becomes (`{ skipped = ShiftForward, ambiguous = Earlier }`, `lenient`, `strict`), never chosen for it; std.tzdb reads the system's tz database by std.filesystem (`TZDB.zone "Asia/Taipei"`) and its own zone (`system`: `TZ`, else `/etc/localtime`), with no libc time-zone call and no provider; Windows, with no tz database, gets an error saying so.
- std.thread's `parFor` is removed: `parFor n count f` is `parMap n f (List.range 0 (count - 1))`.
- std.thread is a library on std.domain, with no provider of its own and no effect: `parMap`, `spread`, `inThreads` and `cores` ask for `Domain.domain <: e`, and the `threads` effect is removed. `spread n c` runs `c i` on each of n domains, in a scope, and gives their answers in order, the first failure by index the caller's; `gather` is removed. `parMap`'s workers are domains taking the next task by `fetchAdd`; `inThreads` runs a `Parallel`'s right side on a domain of its own. They run in JavaScript's one domain too. A million tiny tasks (`x * 2 + 1`) by 4: 0.07 to 0.32 s, each task a `tried` and a `fetchAdd`; primes below 2,000,000 by 4, 0.07 s both.
- boc: a behaviour takes the custodian current where it is spawned, and its body runs with it: in a `with k := Custodian.custody do` (or `contained`), the things its `with`s hold are in `k`'s custody, and the behaviours it spawns take `k` too; an act awaited and the behaviour after it take the one current at the `await`. `scheduled` and `scheduledWithReactor` ask for `custodian <: w`, so a `main` that runs them names `custodian` in its world. A `when` asks the custodian current once more: 900k behaviours 2.70 to 2.81 s.
- boc's `scheduledWithReactor`: a domain looks at its acts finished every 64 behaviours, not after each, where it has other behaviours to run: each look polls every act pending on it. std.http.bocserver with 500 connections held open and idle took each new one only after a look at all of them, too slowly for the listener's queue (128 on macOS), and about a fifth of the idle connections were reset before they were made; now none is. A sequential client 158 to 126 µs a connection, the server's CPU 83 to 65 µs.
- cml's `spawn`, boc's `when` (and a `with` of cowns) and the body after a `BOC.await` are first-order: a thread or behaviour is a closed computation of the scheduler's world, `spawn : Co (cml w <+> w) Unit -> Co e Unit`, `when cs : (Contents -> Co (boc w <+> w) Contents) -> Co e Unit`, and a `with` of cowns or of an await has its body in `boc w <+> w`. None of the handlers between the spawn point and the scheduler is around it any more -- a `recover`, a state, a `with`'s resource -- so what it needs it opens itself or is given as a value; a thread spawning the next from inside its `with` no longer puts each generation's operations through the earlier ones' handlers. `choose`'s branches and `Domain.tried` stay higher-order: they run in the calling thread, in what is around them. `withNack f` gives `f` the nack as a value, so that a thread spawned in the guard can be given it: a `CML.Nack w`, read-only, `CML.awaitNack nack` its base event, readied by the scheduler alone (an ivar there could be forged by a `putIVar`).
- cml: a thread that fails no longer stops its worker: the worker catches it and goes on, the other threads not stopped (one catch around a worker's loop, not one each turn; main's turns catch their own), and the scope collects it -- `scheduled`, `scheduledWithReactor` or the `with _ := CML.threads do` fails, once the run is over, as the first thread that failed did, its words kept. A failure of main's ends the run as its answer would. boc's `scheduled` fails, where a `failed` failed, as the first such `failed` did, instead of abandoning (`\why -> Domain.fail why` makes a behaviour's failure the run's, as it came).
- std.domain's `tried c` and std.fuel's `limited n c` hold `c` as a function of `Unit`, computed where the operation runs it: in a thread of cml's, what `c` computed before its first operation was computed where cml handed the operation on, outside the `tried` (a failure there failed the thread) or the limit (a pure loop there was not stopped). A `tried` hands running out of fuel on, to the limit it is in.
- std.fuel: `limited n c` runs `c` on at most `n` of fuel, `Just` its answer or `Nothing` where it runs out, a watchdog, not a time slice (the computation is jumped or thrown out of, never resumed); a limit within a limit gets at most what is left of the outer, and running out of that is the outer's too. The fuel is the program's ticks where it is built with fuel, else the world's operations alone: there a pure loop runs past its limit, and heff warns at each use of `limited` (W0390).
- std.domain: domains are spawned in a scope, and only there (#138). `with s := Domain.scope do` runs its body in the block's world with the scope's own effect, `Domain.scoped w`, and waits at its end for every domain spawned in it; `Domain.spawn s c` is that effect's, `c` a computation of the world around the `with`, so a domain cannot spawn in its own scope (it opens one of its own). A domain that fails fails the scope, as the first to fail did, once all have ended. Cancelling is cooperative: `Domain.cancel s` sets the scope's mark, as a failing domain or body does, and a domain reads it with `Domain.cancelled s` and winds up as it chooses; no domain is stopped from outside. The `spawn c` of any world is gone. cml's and boc's schedulers run their workers in a scope of their own; boc's waits for its behaviours where main fails, then fails as main did.
- co: a `Binder`'s `Contents` is given the world of the block around, `Contents : HFunctor -> Type -> Type` (`\w s -> ...`), so that a `with`'s names can be of a type that says it.
- std.domain's `fail why`: this domain fails as `why` says, a `tried`'s `Left` handed on with its words, as a join hands on a domain's failure (`"heff:abandon"` abandons). `Domain.spawn` stays as it was, its computation of the spawning domain's world, run under the handlers between it and the program's world; a scheduler is best run in the program's world itself.
- std.http.cmlserver's and std.http.bocserver's `serve err l handle`: the handler is of the scheduler's world and may throw an `err` (`Empty` for none), `Server.Request -> Co (exception err <+> (CML.cml w <+> w)) HTTP.Response` and `Server.Request -> BocServer.Responder w -> Co (exception err <+> (BOC.boc w <+> w)) Unit`: a throw closes that connection at once, unanswered, what was thrown let go of, and the others are served on (it used to abandon the run, the socket open until the value was freed). bocserver's responder, `Responder w`, answers from whichever world has boc's behaviours.
- std.http.cmlserver's `serve err l handle` is of a cml thread's world, `Co (CML.cml w <+> Custodian.custodian <+> w) Unit`, not of any world with cml in it, so its `w` is found from where it runs -- `CML.spawn (CmlServer.serve Empty l handle)`, a function of a thread's world -- and needs no `(w := w)`. A `choose` around it says no world of its own, and is given it, `CML.choose (w := w)`.
- std.net's `withListener` throws nothing: `withListener address backlog body` comes to an `Either NetError a`, a `Left` where the socket does not listen (the body not run) or does not close after it, so it asks for no `exception NetError`, and a scheduler run in its body -- for std.http.cmlserver or std.http.bocserver -- is stacked on the program's world itself, no handler of the program's between it and the domains (`attempt NetError (Net.withListener ... (\l -> lift (BOC.scheduledWithReactor ...)))` is `Net.withListener ... (\l -> BOC.scheduledWithReactor ...)`). `accept` throws as before.
- std.signal: a program waits for the signals it is sent, `Signal.wait [Terminate, Interrupt]`, the first of them to come (`Signal`: `Interrupt`, `Terminate`, `Hangup`, `Quit`, `User1`, `User2`, `WindowChanged`; `show` gives `SIGINT` and so on). C only, not on Windows. A signal waited for is the program's from then on: it no longer ends the program, and one that comes while no wait is pending is kept for the next. A wait is an outside operation of std.reactor's: under `CML.scheduledWithReactor` it is pending while the other threads go on, and in a `choose` a base event, so a `choose` of std.http.cmlserver's `serve l handle` and `Signal.wait [Terminate]` serves until SIGTERM (its header shows it). A signal not waited for is as before: SIGINT, SIGTERM and SIGHUP end the program and the commands std.process started.
- Each error type's message is its `Show`: `show err` of std.filesystem's `FileError`, std.process's `ProcessError`, std.net's `NetError`, std.http's and browser.http's `HttpError`, browser.gpu's `GpuError`, remote's `RemoteError` and ffi's `Errno`. `showFileError`, `showProcessError`, the `showError`s, `showRemoteError`, `showErrno` and json's `showParseError` are gone.
- std.file: a file opened by `open`, closed by `close`, and what the system says of it by `stat`; read and written a piece at a time (`readChunk`, `readLine`, `writeBytes`, `writeString`, `seek`, `tell`, `foldLines`, `copyOpen`), and the standard streams as files. Each takes the `File` itself and throws a failure, a `FileError`, over the `exception` effect, as std.filesystem's operations on a path do (no `Either FileError` answers); `with f := File.open path do` is `open` and `close` around its body (`withFile` is gone). What a file is opened for is an `Access`, `Read`, `Write w` or `ReadWrite w`, where `w` says, as Racket's `#:exists` does, what is done with a file there (`Error`, by default: it must be new; `Truncate`, `MustTruncate`, `Replace`, `TruncateOrReplace`, `Update`, `CanUpdate`, `Append`) and the permissions of one made (`0o666`). These leave std.filesystem, whose open file is now `File`, and `OpenOptions` is gone: `withFile path { access = Write } body` is `with f := File.open (access := Write { exists = Truncate }) path do`, `{ access = Append }` is `(access := Write { exists = Append })`.
- cml: an event is a computation run to its commit point (#130). `send`, `recv` and `readIVar` are the base events; `choose cs` runs each branch up to its first base event, commits one, and what follows it is the wrap; `withNack f` gives `f` a nack, ready once its branch is abandoned for another. `Event`, `sendEvt`, `recvEvt`, `readIVarEvt`, `always`, `wrap`, `guard` and `sync` are gone: a branch that ends first is `always`, the statements after a base event are `wrap`, those before it `guard`.
- cml: `scheduledWithReactor c` is `scheduled` with each domain waiting on the world through a reactor of its own (#130): a thread's operation that would wait (a socket read, an accept, a request, a sleep) is pending, the others running meanwhile, and in a `choose` such an operation is its branch's base event, let go of, undone, where another commits first, so `choose [recv ch, Time.sleep d]` is a time limit. 64 threads sleeping 300 ms at once take 0.3 s; an idle worker waits in its reactor, woken by a pipe.
- cml: a scheduler's scope as a `with` (#130): `with _ := CML.threads do ss` runs `ss` as cml's main thread, in the block's world with cml (`cml w <+> w`), its threads on domains as by `scheduled`, and comes to `Just` main's answer (`Nothing` where every thread waits); the `with` is done once the scheduler is, no thread of it left after the block. `CML.threadsWithReactor` is the same as by `scheduledWithReactor`. A body's operations whose world `w` is not known by its types are given it, `said (w := e)`, as with `scheduled`. `scheduled` and `scheduledWithReactor` stay.
- std.reactor is no scheduler (#130, #132): `scheduled`, `together` and `outside` are gone (green's `Outside` with them). New: `openWithin g`, a group within another, pending and finishing among its, closed apart; `pending g`; `wake g`, which wakes the domain waiting in `finished g True` from any domain. Group numbers are unique across the system's threads.
- boc: acts of the world awaited, as Verona's behaviours await them: `with r := BOC.await act do` (`Await`, `await`) runs `act` outside every behaviour, and its body is a behaviour once `act` has come to `r`; `with x := c` and `r := BOC.await act` under it, a behaviour on `c` then, so no cown is held while the act waits, and behaviours on a cown come in the order their acts did. The `with` waits for nothing. `scheduledWithReactor failed c` runs each act in a reactor group of the domain whose behaviour awaited it, after that behaviour; a domain with nothing to run waits in its reactor; the run ends once no behaviour runs or is ready and no act is pending; an act that itself fails (abandons, or fails in the runtime) is as a body that fails: `failed` is given why, its body is not run, and the others go on. Under `scheduled`, an act runs where it is awaited. A `with` of cowns has `instanceBinderCowns`/`instanceHolderCowns` for two cowns and `instanceBinderCownsMore`/`instanceHolderCownsMore` for more, so that `(Cown, Await)` is found by the await's alone.
- std.http.bocserver's `serve l handle` is written on `BOC.await`: every wait of the server -- an accept, a read, a write -- an act, each step a behaviour on the connection's cown, so as many connections are served at once as come, none holding a domain while it waits (200 kept open at once, on fewer cores). The handler is given a responder, `Server.Request -> (HTTP.Response -> Co e Unit) -> Co e Unit`, and may answer later, after acts of its own. `serve` comes back at once and runs in behaviours, under `scheduledWithReactor`, anywhere: it stops where a connection cannot be accepted -- the listener closed by `Net.closeListener`, say on `Signal.wait [Terminate, Interrupt]` -- connections waiting for a request closed at once, the others once the request in hand is answered, and the run ends.
- std.net: `accepted l`, the next connection in the listener's region, not held by a `with` of its own, closed by `close`; `closeListener l` closes a listener before its `with` ends, an `accept` waiting on it done at once. A connection or a listener closed again, by these or by its `with`, is left as it is. resource's `beside w x` has `x` in the region of `w`'s thing.
- std.reactor's `open (failed := Just f)`: each step of a computation started in the group runs under a catch, and one that fails is finished as `f why`, the others going on; without `failed`, a failure is the program's, as before.
- std.http.server's `requestIn peer bytes`: what the bytes read so far of a request come to, read at once (`Right` a `Got`, else `Left` its head, where read, and how many bytes in all it wants).
- std.http.server serves one connection at a time; `serveConcurrently` is gone. A server of many at once is a module of its own, each with a `serve`: std.http.cmlserver's serves each connection by a cml thread, std.http.bocserver's on boc's behaviours, every wait an act awaited (above).
- `parseFloat : String -> Maybe Float64` (the prelude's) and float32's `parseFloat32` read a decimal, correctly rounded, by the runtime: zig's `std.fmt.parseFloat` in C, `Number` in JavaScript (and, for a `Float32` where rounding twice could differ, an exact comparison). json's `parse` reads its floats so: 3 million floats of 17 digits 1.20 s to 0.23 s in C, 8.0 s to 1.8 s in JavaScript.
- A float literal at `Float32` is rounded once, to the `Float32` nearest the decimal it writes, not first to a `Float64`: `(1.0000000596046448 : Float32)` is 1.0000001, not 1.0. float32's `fromDecimal` rounds so, as std.math's `fromDecimal` does to a `Float64`.
- `debug` of a `Float64` or a `Float32` is a literal heff reads back as the same float, still the fewest digits: an exponent has a point before it and no `+` (`1.0e23`, `5.0e-324`, `1.5e300`, not `1e+23`, `5e-324`, `1.5e+300`), and -0.0 keeps its sign (`-0.0`, not `0.0`). `NaN`, `Infinity` and `-Infinity` are as before. json's `stringify` writes numbers as before, as JavaScript does.
- std.map is renamed std.ordmap, and its type `Map` `OrdMap`: the name says what it asks of the keys, an `Order`.
- std.map: the theory `Mapping c` of a map of any kind, with `Key` and `Value` as its fields: `empty`, `insert`, `lookup`, `remove`, `size` and `foldl`, and an instance for std.ordmap, std.hashmap and std.hashtable, so that one definition serves all three and a program picks one by its type.
- check: `within ms t` is now `withinTime ms t`, `within` being co's.
- co: `within h e alg c` runs `c` with what `h` does said within the handler of the rest: `alg` is given that handler and answers in its monad, so no `Co e` stands between `h` and `e` as in `through`. A query handed on through many such layers builds nothing at each (handler_sieve 4.9 s to 0.48 s). The answer is the outer handler's to bind: the same as `through`'s where that handler keeps the monad laws.
- array: `push`, `pop` and `reserve`, and `insertAt` and `removeAt`: pure functions like `set`, changing an array in place where nothing else holds it and copying it first where something does. An array keeps room past its length, doubled when it runs out, so pushes are amortised O(1); `append` grows a unique left array in place. `pop` gives `Maybe (Pair (Array a) a)`. (#115).
- array: `pop` is made of `removeAt`, which now shortens an array nothing else holds in place: a `case` on it where it is called builds neither the `Just` nor the pair. The primitive `arrayPop` is gone.
- std.filesystem: an operation on a path that fails throws why, a `FileError`, over `exception FileError`, instead of giving a `Maybe`, a `Bool` or an `Either`: `readFile` gives the text, `writeFile`, `makeDirectory`, `remove`, `copy`, `move`, `replace`, `readOnly`, `writable`, `setMode` and `makeExecutable` give `Unit`, and `pathStatus`, `linkStatus`, `realPath`, `temporaryDirectory` and `temporaryFile` their value. `readDirectory` gives what the directory holds as paths in it (`dir / name`), sorted. `readLink` gives what a link says, as it was written. `exists`, `isFile`, `isDirectory` and `kindAt` still answer without a throw; an operation on a file open still gives an `Either FileError a`.
- green is removed (#132): threads are cml's, on std.domain, and what waits on the world does so through std.reactor under `CML.scheduledWithReactor`.
- boc: `scheduled failed c` takes what is run where a behaviour's body fails (#131): `failed why` runs on that behaviour's domain while it still holds its cowns, which then hold what they held and go to the next behaviour; `scheduled` gives main's answer. Where a `failed` fails too, `scheduled` abandons once every behaviour is done, so `\why -> abandon` makes any failure the run's. std.domain's `tried : Co e a -> Co e (Either String a)` is no longer provisional.
- std.reactor: a thread's outside operation is begun and ended by first-order operations, `Begin` and `End`, run in the world's own course, not held by a `Start` that held the computation. A stateful handler between the scheduler and the world (`runState`) kept nothing an outside operation wrote: it ran the computation an operation held from its state of the time and dropped what it left. It now sees each operation as any other.
- `Order` carries its type's `Equality`, the field `eq`: every `Order` instance gives one. `ord.eq.equal`, or `(==) (eq := ord.eq)`, compares by it; `==` still finds only an `Equality` in scope. `orderByCompare` takes the `Equality` as an instance argument.
- std.time: two clocks, both in nanoseconds (as `Status.modified`): `now`, the time of day since the epoch, and `monotonic`, for elapsed time. C reads `clock_gettime` (`CLOCK_REALTIME`, `CLOCK_MONOTONIC`), JavaScript `Date.now` and `performance.now`.
- std.filesystem: `readBytes` gives a file's `Bytes`, as `readFile` gives its text, failing the same way.
- std.io: `flush` writes what the output has kept: to a file or a pipe, the output is written a buffer at a time, so a long-running program's `print` showed only at its end. `flush` is a new operation of `stdio` (`Flush x`): a handler of `stdio` written in the language needs a case for it. Bytes already reach the output unchanged by `write (Bytes.asString b)` or std.filesystem's `withStdout` and `writeBytes`; `Bytes.show` (std.http's `text`) is what turns bytes that are not UTF-8 into U+FFFD.
- Time limits on what waits. std.net: `withConnection`, `read` and `write` take a `timeout` in milliseconds, by name (`Net.read (timeout := 500) c 4096`); where it passes first the operation fails `ETIMEDOUT`, a connection not made closed, a stream still usable. 0, the default, waits as before. The limit is kept with std.reactor's scheduler or without one, by the poll the operation waits in; without one, a host's name is resolved by getaddrinfo, not cut short. std.http: `Request` has `connectTimeout`, how long the connection may take to be made (libcurl's `CONNECTTIMEOUT_MS`, the spawned curl's `--connect-timeout`), apart from `timeout`, the whole transfer's; either is curl's code 28. std.http.server: `serve`, `serveUntil` and `serveConnection` take an `idle` limit by name, as std.http.cmlserver's and std.http.bocserver's `serve` do, 30 s by default (0: none); a client that sends nothing for that long, between requests or within one, is closed.
- std's errors say what they are of. std.filesystem's `FileError` has the `path` the failing call was given, as the program wrote it -- in a tree (`copy`, `remove`, `readOnly`) the one inside it, of an open file the path it was opened by -- and, where the call took two (`move` and `replace`'s rename), the `other`; `show` writes `path: NAME: message`, or `path -> other: NAME: message`. std.process's `NotRun` carries a `ProcessError`, which has a `path` too: the command, or the `dir` where that was not there (`show`). std.net's `NetError` has the `address` (`host:port` as given, or an accepted connection's other side), std.http's and browser.http's `HttpError` the `url`, and their `show` says them. json's `ParseError` is a record of the `offset`, the `line` and the `column` (in characters) and what was `expected`; `describe`, and its `show`, says `line 2, column 8: expected a value`. heff's own messages say them: a program not run, a test's directory not made, a `zig` or `git` not there.
- regex reads more of RE2's syntax and finds what it matches, by an NFA's threads side by side (linear in the string, as Go's `regexp`): groups `(...)` and `(?:...)`, counts `{n}`, `{n,}`, `{n,m}`, lazy repetitions (`*?`), `\d`, `\w`, `\s` and their negations, `\b`, `\B`, `\A`, `\z`, `^` and `$` anywhere, and runes, not bytes: `.` is any rune but a line break. `find`, `findIndex`, `findAll`, `findAllIndex`, `submatches`, `replaceAll` (`$1`, `${1}`, `$$`), `replaceAllWith` and `split`, as Go's. `heff test --run` cuts its levels at a `/` outside a group too.
- string: `replace`, `repeat`, `cut`, `lastIndexOf`, `occurrences`, `trimPrefix`, `trimSuffix`, `trimStart`, `trimEnd`, `padStart`, `padEnd`, `toUpper`, `toLower`, `equalIgnoringCase`, `showIntBase` and `parseIntBase` (bases 2 to 36), and `showFixed x places`, a float to a fixed number of places, exactly (Go's `FormatFloat(x, 'f', n, 64)`).
- list: `concat`, `index`, `indexed`, `indexWhere`, `count`, `mapMaybe`, `partition`, `takeWhile`, `dropWhile`, `span`, `split` (at an index), `group` and `unique` (by the elements' `Equality`), `intersperse`, `unzip`, `scanl`, `minimum` and `maximum` (by their `Order`). array: `search`, the least index a predicate holds from (Go's `sort.Search`). std.set: `intersection`, `difference`, `keepIf`, `isSubset`.

### Backends and performance

- C: a lambda's body takes what its closure holds where it first gives one of them up, down each arm of a test or a match it ends with, not where it starts; a way through it that only reads and drops them drops the closure, once. A closure called again and again -- a resumption called for each choice -- counts what it holds up and down no more at each call (#150). nqueens_amb 15.84 G to 14.21 G instructions, 0.82 s to 0.74 s.
- C: an `Int`'s sum, difference, product, quotient and remainder lend their operands (`heff_intAdd_lent` and the others), as a comparison does, and an operand beside one lent may be computed of primitives that give nothing up, so `q /= q2 + d` takes no reference of `q`, `q2` or `d` (#150). nqueens_amb 17.55 G to 15.84 G instructions.
- C: `sin`, `cos`, `tan`, `exp` and `log` are, where zig's compiler_rt would give its own (on Linux, and with musl; its `exp 1.0` was a unit in the last place off), the runtime's own, fdlibm's as V8 has them, the same as JavaScript on x86-64; on macOS they are the system's. V8 for arm64 fuses some of fdlibm's steps, and may still differ there in the last place (#124).
- Fuel, the compiler's part (#133), opt-in: a program built with fuel (build.hf's `fuel = True`, `heff compile --fuel`, `heff bench --fuel`) ticks at the entry of every function that may be entered again before it ends (it calls a function of its own recursive group, or a closure), a decrement and a branch on a count each domain has, so that std.fuel's `limited` stops any loop, one doing no operation too. A program built without it is compiled as before, byte for byte (the compiler's own C, 355 files, the same). The leak is said plainly: with fuel every loop pays, a tight pure loop 558 to 734 ns per thousand rounds, the state handler's 460 to 575 ns, an array's float sum 2.2 G to 12.2 G instructions (the branch keeps C from unrolling it), the compiler compiling itself 112.8 G to 121.6 G instructions.
- Fuel: a loop calling itself last and nothing in its rounds is ticked once a batch of its rounds, its body copied `k` times (about 64 of the IR's nodes a batch, 1 to 64 rounds, `Fuel.batchMost`), charged `k` at the batch's head: a thousand-round count 783 to 610 ns (638 without fuel), the state loop 595 to 411 ns (459), the float sum 12.2 G to 9.5 G instructions (2.25 G: its copies are each checked in range). `limited` stops such a loop up to a batch before its limit, and charges up to a batch more each time it is entered. The compiler's C built with fuel 31.45 MB to 33.57 MB (30.95 MB without).
- std.fuel in JavaScript: a limit is the computation's, as on C. Each computation has a context of fuel -- its count and the limits open in it -- an operation's continuation goes on in the context it was performed in, and a provider runs in one of its own; so a `limited` holds across a sleep or a fetch and across other domains' turns (a domain spawned in a limit runs with none), where its count used to go on in whatever ran next and running out was thrown to the page. Programs without std.fuel are as before; with it, each operation switches contexts.
- `heff run --fuel FILE` and `heff test --fuel` build with fuel, as `heff compile --fuel` and `heff bench --fuel` do, for a program with no build.hf; `heff build`, `install` and `dev` take it from each program's build.hf.
- Fuel: a counted loop (an index tested against a bound the loop keeps, stepped by a constant) tests once a batch whether all of it goes round, and then runs its rounds' copies with no test between them, a read of the bound's array at the index unchecked (`arrayIndexIn`, JavaScript's too); the last rounds go one at a time, the batch's charge given back. Its batch is of about 256 IR nodes. The float sum with fuel 0.60 s, 9.5 G instructions to 0.53 s, 2.34 G (0.53 s, 2.24 G without fuel); clang makes the batch 25 straight `fadd`s on paired loads, as without fuel it unrolls the loop by 8 (the sum's order kept, neither vectorises its adds).
- C: a string or bytes grown in place by at most 64 bytes copies them by loads and stores, not by a call to `memcpy` (a byte at a time below 8): building a string a piece at a time, base64, base32, hex, html, 3.3% fewer instructions; inflating, 1%.
- In `run do`, an `if` or a `case` statement whose arms each reach their end is no join point: each arm gives the variables back to what follows, as a loop does (`MkPair`s). A match's value bound and taken apart at once, every way out building the tag taken apart, written so or by hand, is copied into the arms or, past the simplifier's budget, the names it binds set in each arm (`ESet`), no tag built. A loop whose `if` and the loop called each other last was one `$cycle`, its numbers boxed: 3.7 s to 2.7 s over 300M turns.
- Conditions are a language of their own from the simplifier on (`EBool`: comparisons, `not`, `&&`, `||`, a `Bool` looked at): an `if` is a match on one and builds no `Bool`, and the passes after it take it as it is. The compiler's C 33.61 MB to 33.38 MB.
- In `run do`, a loop is a function of its own that gives its variables back where it ends, what follows it after the call, not a function it calls last: a loop in a loop is a loop of its own, its numbers unboxed, not one function of them all. `matmul` (a `for` nest) 6.7 s to 1.07 s (#113).
- Loop accumulators stay unboxed: a `Float64` total in a `do` loop is boxed once at exit. `doloops_float_do` 7.40 G to 0.42 G instructions.
- `Array.set` in a loop that uses the array linearly checks uniqueness once on entry, then writes in place, so the C compiler vectorises the loop (#102).
- A loop reading and setting arrays at an index checks the bounds once on entry. `saxpy` 0.48 s to 0.30 s (#102).
- `generate` of a lambda giving one fixed-width number builds the array flat, and in-range reads of it are unchecked. `Int64` sum 0.40 s to 0.13 s (#102).
- New numeric array benchmarks: sums, dot product, `saxpy` and `Array.map` over ten million elements (#102).
- In threads mode, a shared object whose count is back to one is reused in place again, as an owned one is. A fold over a shared 16M-node tree: 0.54 s to 0.39 s.
- A stack overflow is an error, not a crash: a C program says `heff: stack overflow` and exits with 2, from any thread heff starts. Where a failure is caught, so is an overflow, as "stack overflow": a std.thread worker hands it to the thread that joins it, and a language server request fails alone. `heff check` on a file nested too deep says so, and the language server reports it on the file and keeps serving. Catching a failure no longer saves the signal mask.
- A program using threads built as parts (`heff build`, `heff compile DIR/`) no longer crashes: every C file now sees threads mode, not only the one with `main`.
- The continuations a recursive copy is handed by its own group are tags, not closures, where every one that may reach a call is known and goes nowhere else: their free variables the fields, a call of one a call of a function choosing its body by the tag (defunctionalization, within the group alone), a call of itself last a loop. tree_explore 4.4 s to 3.3 s.
- A rune and its width read at the same byte, as `runeAt s i` reads them, are decoded once, by a primitive giving both; an ASCII byte is read where it is, not by a call. In C, str_runes 17.8 G to 9.8 G instructions, graphemes 25.3 G to 23.3 G; in JavaScript, str_runes 7.2 s to 6.0 s. `fromRunes` counts its bytes without encoding each rune twice.
- C: a provider may lend the process's first thread to a toolkit that must have it (AppKit's, UIKit's run loop), `heff_first_thread(run, stop, u)`, and ask `heff_is_first_thread()` (#142): `run(u)` runs there while the program goes on on its own thread; at the program's end, however it ends, `stop(u)` is called and `run` waited for, or, with no `stop`, the program exits without it. A program that lends nothing ends as before.

### Compiler and tools

- `M.x`, where the module imported as `M` defines `x` but its claim does not list it, says `` `x` is defined in `m` but not exported`` (E0353), not that `M` is read as a tag.
- A metavariable applied past its arity, as `?m t` of a `?m : Type -> Type` under a binder `t`, has the type it comes to applied to all its arguments where it is pruned, or stands in another's solution: such a program (`first fixed made t`, `x : Of made -> Int`) aborted the compiler with `heff:abandon`, and now elaborates, or says what it cannot infer.
- `heff dev` builds and runs, and no longer serves pages: `heff dev-pages`, `--port` and `--proxy` are gone, and heff links no network or HTTP client.
- `heff dev-pages` serves up to 16 connections at once, each a computation of its own in a group of std.reactor's, no threads (it was green threads), so heff stays a program of one thread.
- The interpreter (doc tests, watches, `heff eval`) tells a loop from a recursion: a call in a tail position, a function's body applied or a match's arm, nests no deeper, so a loop runs as long as it takes up to a hundred million steps, and only what waits for a value nests, up to a million (#128). A tail loop of ten million turns, or JSON nested 500000 deep, is no longer `<diverged>`; `spin x = spin (x + 1)` still is, after about 7 s.
- `heff fmt`: a block that is an application's last argument, `f x (case y of`, laid out on a line of its own (after `=`, or a lambda's arrow), has its items indented from that line, as a statement's are, not under the application's first token.
- The language server goes to a local's definition, its binder, and highlights a name's occurrences in the file. References and renaming elaborate only the files whose text has the name, the rest thawed from the cache, and keep what they elaborated until it changes: references of `IR.Expr` in heff's own project take 1.8 s the first time and 0.7 s after an edit, not 10 s each time; a local's references are found in its file alone. A module claim's entry is a reference too, and is renamed.
- `heff get` takes a package no tag is a version of at a pseudo-version, `0.0.0-TIME-COMMIT`, of its default branch's commit, or with `PATH@BRANCH` or `PATH@COMMIT` of that commit. A pseudo-version is older than every release.
- A C program can be linked with a library or framework that is not the runtime's (#141). A module whose C needs one says so with a definition of type `FFI.Links` (`{ pkgConfig = ["unibilium"] }`, `{ libs = ["objc"], frameworks = ["AppKit"] }`), and every program that imports it is built with pkg-config's flags, `-lNAME` and, on macOS, `-framework NAME`, by `heff build`, `heff run` and `heff test`; a provider includes the library's header and calls it, with no `dlopen`. A program's `build.hf` can add `includeDirs` and `libDirs`.
- `heff compile --backend=c` without `--name` runs `main`, as `--backend=page` now does too, not each definition shown nor the first computation that fits; a file without the definition is refused, naming it. OUT in a directory that is not there is refused, `heff compile: DIR: no such directory`, for every backend, and a file `compile`, `promote` or `fmt` cannot write is said, not an exit 1 with no word. The tests' C program of each definition is `heff dump-c FILE OUT`.

## 0.5.0

Released 2026-10-16.

### Language

- `do` blocks have imperative statements: `let mut` and `:=`, `while`, `for` over anything `Iterate`, `break`, `continue`, `return`, and `if` without `else` (#86).
- `do` also has `if let`, and `try ... catch` over the exception effect (#100). `try` takes only exceptions, and its `catch` arm is required.
- `do` has a `with e as x do` statement: the rest of the block is the body of a scoped resource (#106). `with` and `as` are keywords.
- `while True` and `if True` work: a bare tag as a condition is read as the built-in `Bool`.
- `mutual` blocks define mutually recursive functions, each with its signature. The formatter lays them out, and the elaborator checks them with the errors worded as the text has the names.
- Every file begins with `module a.b`, optionally listing what it exposes, as in `module (x, T, U(..))`. A missing or wrong name is E0156, another name for the claim is E0157, hiding a name or tag is E0353 (#101).
- `Coe from to`: where a type mismatches and an instance of `Coe` between the two is in scope, the coercion is inserted. `String` is taken as a `Path` this way (#105).
- `Monad` is a theory in the prelude, with `traverse`, `foldM`, `when`, `unless` and `replicateM` written once. `>>=` is an operator.
- A local hides an alias.

### Standard library

- `std.path`: `Path` is its own opaque type. `parse` and `render` take the style (`os`, `native` or `onWindows`). `std.filesystem` and `std.process` take and give `Path` (#105).
- Host things (files, processes, connections, listeners, GPU devices and buffers, DOM elements) are foreign values held by a `with` (#99).
- The `resource` module holds `With s a` and `scoped acquire release body`, one scoped resource for every effect. A resource that cannot be acquired or released is thrown over the exception effect, never returned as an `Either`.
- `std.filesystem`: `withFile`, `withStdin`, `withStdout` and `withStderr` hold a file or a standard stream for a body.
- `std.process`: `withProcess` holds a subprocess, which is ended (SIGTERM, then SIGKILL after two seconds) when the body ends. `run` takes an `Invocation` and gives a `Ran`. Waits and pipe reads are pending in the reactor, so they block no other green thread. `workingDir` and `setWorkingDir` are new.
- `std.net`: `withConnection`, `withListener` and `accept` hold sockets. `std.http.server` has `serveConcurrently`, serving each connection in its own green thread.
- `std.reactor` waits may have a deadline, so a `sleep` lets the other green threads run (#97).
- `browser.dom`: the document comes from `withDocument`, and elements are host values passed by value. `browser.gpu`'s `dispatch1` to `dispatch3` take buffers one by one.
- Acronym aliases are written in capitals.
- New `ffi` module: C types as values (`CType`, `CResult`, `Described`). A provider can be described in C and the compiler writes its glue (#99, #97).
- `onWindows` says whether the program is built for Windows.

### Compiler and tools

- `heff test --watch` reruns tests whenever a tested file changes. `heff test` with no file also runs the project's doc tests.
- `heff bench`: a `Bench` definition found by type, built at `-O2`, run in its own program with Go-style counts and lines (or JSON). Options `--run`, `--time`, `--count`. Objects made are counted when built with `HEFF_COUNT_ALLOCS`.
- `heff doc` writes a Markdown API page for each module from its module comment and doc comments, with signatures laid out as `heff fmt` does them. `--out DIR` writes the pages and an index.
- `heff init` takes the package name from the working directory on every system, and refuses a directory that cannot name a package, saying the rule.
- LSP: quick fix for E0156 and E0157 writes `module <name>`. The VS Code extension writes the header of an empty `.hf` file it opens (#101). Types shown on hover are the solved ones. `mutual` is highlighted as a keyword.
- Loading a file by a relative path from below the project root finds the root above the working directory.
- Pending instance arguments are searched as soon as their goals are known, so what an instance fixes (a type member) is known to the code after it.
- The runtime's fault message no longer uses `std.debug.print`, which cut about 1.1 s from every program's zig build (ReleaseSafe 1.4 s to 0.4 s).
- A SIGTERM arriving while a command starts no longer leaves the command running (`heff dev` shutdown).
- A Nix flake builds heff from the seed; the README installs by `make`.

### Backends and performance

- Parts of the C runtime are rewritten in Zig and linked into every C program: big integer arithmetic, bit helpers, UTF-8 reading and writing, hashes and float formatting. Floats are printed by Ryu, with the same text as before.
- Strings: slices of 64 bytes or more, and at least a quarter of their root, are views of it, so taking a tail again and again no longer copies.
- Threads mode allocates in pages owned by the creating thread. `queens` runs 10-15% faster at 4 or more threads, and a make-here, free-there loop no longer grows (#66).
- Mutually recursive cycles no longer drop parameter pads on each round. `matmul` 4.6 s to 3.2 s.
- `simplify` moves the arms of a match on a match into the ways out choosing them, with no copying. `edit_distance` 450M allocations to 30k, 2.55 s to 1.71 s.
- An unboxed worker is made for a loop that rebuilds its tag argument at each call. `doloops_pure` array loops 0.44 G to 0.24 G instructions.
- Reading an `Int` from a lent array is lent, so a `do` loop over an array no longer dups and drops each element.
